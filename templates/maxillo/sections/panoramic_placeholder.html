{% comment %} The saved-panoramic pane's "there isn't one yet" state. Deliberately *not* the `.panoramic-error` block beside it. "No panoramic yet" and "the image failed to load" are different facts, and sharing one box meant every newly uploaded patient was greeted by a warning triangle. Included twice -- once for the inline card in the CBCT tab, once for the standalone Panoramic tab -- with an `id_prefix`, because both panes show the same patient and there is nothing to say twice. `static/js/modality_viewers/panoramic.js` toggles the container by id, exactly as it toggles its loading/content/error siblings; the message and the button carry data attributes instead, because there are two of each on the page and `frontend/imaging/panoramic/placeholder.js` writes both in one call. The same reason `[data-panoramic-variant-controls]` is a data attribute. The wording shipped here is the terminal one: a page whose `panoramic-cpr` bundle never runs shows an honest static message rather than a spinner that never resolves. The bundle takes ownership by rewriting it -- the same contract as the Edit-arch button, which the template ships `hidden` for the same reason. {% endcomment %}
