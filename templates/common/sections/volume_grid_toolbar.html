{% comment %} Annotation mode. A switch rather than a button, and off by default: a clinician opening a study is reading it, not measuring it, and the seven measurement buttons plus a save button on a toolbar that is mostly used for reading were simply noise. `role="switch"` with a visible on/off word because "is this eye icon telling me the state or the action?" is exactly the ambiguity that got reported -- the same reason the previous eye button could be clicked in the belief it was *enabling* something while it hid. One control, two effects, and they are deliberately the same control: turning the mode on reveals the tools **and** shows the annotations. A separate visibility button meant two states that could disagree, which is how "I clicked show and saw nothing" happened. {% endcomment %} {% comment %} Measurement tools. The roadmap's "Why" table opens with "one measurement tool exists, and it is never saved" -- these are the tools that close it, and every one of them persists through `annotations/services/viewer.py`. `data-ygg-tool` is the Cornerstone tool name; `frontend/imaging/grid/controls.js` binds whatever is present, so a tool can be added or removed here without touching the JavaScript. `hidden` here is the default state, not a decoration: `bindControls` re-asserts it on load so the DOM and the grid cannot start out disagreeing. {% endcomment %}
